# 監控 AI 指令範本

長時間救援的分工是：**使用者**做所有決定，**開發用的 AI** 寫程式與分析問題，**執行用的 AI** 只負責啟動程式與定時轉述回報。這份是交給執行 AI 的指令，複製後把 `<...>` 換成實際的路徑。

這次實際用過的執行 AI：Antigravity 裡的 Gemini（9/13～9/16），之後改用 Claude Code 的 Sonnet 搭配 `/loop`（9/16 起）。

寫這種指令的原則：

- **角色講清楚**：只啟動、轉述、照表處理。不改程式、不刪檔、不自己判斷、不自己想其他辦法。
- **允許的指令列出來**。這次在 Antigravity 的允許清單只放行 `python`，其他指令會跳出確認畫面，使用者在睡覺就會一直卡住。
- **每一種回報狀態都寫出「要不要叫人」**。多數狀態是正常的，照常轉述就好，只有少數幾種要叫人。
- **一律用繁體中文回報，每次都給數字**，不要只給印象。

## 範本一：方法一（Windows 逐檔複製）

```text
你的角色是「執行與轉述」，不是判斷、不是修程式。程式 rescue.py 已經寫好，會自動續傳、自動跳過壞檔。
你只負責啟動和每 5 分鐘回報。全部自動完成，不要等我回覆。

鐵則（違反任何一條就停下來回報我）：
- 不可以修改 rescue.py 或 <WORK> 底下任何檔案；不可以自己寫程式或用其他工具搬檔案。
- 不可以碰 E 槽：不列目錄、不掃描、不開檔案。唯一允許的檢查是 Test-Path E:\ 。
- 不可以執行 CHKDSK / SPOTFIX / Repair-Volume / Set-Disk / pnputil / taskkill，不可以刪除 rescue.lock。
- 除了下面列出的指令，不要執行其他指令。

步驟：
1. Test-Path E:\ 。是 False 就停下來告訴我「請拔掉硬碟電源休息後重插」。
2. 啟動：python "<repo>\method1_windows_copy\rescue.py" --restart   （其他資料夾用 --restart others）
   - 「新版已啟動」或「新版已經在執行中」＝成功。
   - 「請直接再執行一次 --restart」＝再執行一次。
   - 「啟動失敗」＝停下來把訊息貼給我。
3. 用 /loop 5m，每次執行 python "<repo>\method1_windows_copy\rescue.py" --wait-report 0
   然後用繁體中文 3～5 行回報：時間、狀態、目前資料夾（第幾個／共幾個）、目前檔案、這 5 分鐘新複製幾檔、有沒有新壞檔（有就寫檔名）。
4. 狀態怎麼處理：
   - 「執行中」「卡在壞軌」：正常，照常轉述。
   - 「已記成卡住(壞軌)，強制結束程式並自動重新啟動」「程式強制結束中…已等 N 分鐘」：程式自己在處理，照常轉述，
     不要執行 --restart。強制結束中超過 60 分鐘才提醒我。
   - 「回報已經 N 分鐘沒有更新」或「程式是否執行中：否」而狀態不是「已完成」：醒目地告訴我。
   - 「硬碟疑似卡死」：停止 /loop，醒目地告訴我要拔硬碟電源休息，然後等我。
   - 「已完成」：停止 /loop，總結新複製幾檔、壞檔幾個、哪些資料夾整個讀不到。
5. 「E 槽斷線」超過 30 分鐘、或「等 Google Drive 上傳釋出暫存空間」超過 2 小時，才提醒我。
```

## 範本二：方法二（虛擬機 + ddrescue）

```text
你的角色：只負責「啟動 → 每 N 分鐘轉述進度 → 一輪結束回報 → 等我確認下一輪」。
不要修改任何程式、mapfile、domain 檔、dd.sqlite；不要做任何 USB 重置；不要刪檔。
給我看的內容一律用繁體中文，每換一個步驟都要通知我。

程式：<repo>\method2_vm_ddrescue
執行期檔案（資料庫、日誌、批次報告）：<WORK>
產出與進度回報：<REPORT_TXT 所在的資料夾>
操作手冊：<repo>\docs\方法二_虛擬機ddrescue.md

== 開始前檢查（每一輪開始前都做）==
1. cd <repo>/method2_vm_ddrescue && PYTHONIOENCODING=utf-8 python rescue_dd.py batches     → 看下一批是哪一批
2. PYTHONIOENCODING=utf-8 python rescue_dd.py vm-check
   要看到「共用資料夾已掛載，硬碟 …（唯讀），Windows 沒有抓到硬碟」。失敗就停下來告訴我。
   硬碟通電後約 7 分鐘才就緒，vm-check 可能要等，不要一直重試（隔 5 分鐘試一次）。

== 啟動 ==
用 Bash 工具 run_in_background=true 執行（不要加 &）：
  cd "<repo>/method2_vm_ddrescue" && PYTHONIOENCODING=utf-8 python rescue_dd.py copy > "<WORK>/ddrescue_copy_輸出.txt" 2>&1
- 程式說「這一批要先問使用者」時：問我，我同意後才用 copy --batch bNN。
- 啟動後告訴我：第幾批、內容、檔案數、GB。

== 監控（/loop 每 N 分鐘）==
每次：
- 讀 <REPORT_TXT>，一兩句轉述：讀到幾 %、壞區多少、目前讀到硬碟哪個位置、已救回幾個檔、C/G 槽剩多少。
- 讀 <WORK>\需要處理.txt：空的或不存在 → 正常；有內容 → 裡面寫了原因與我該做的步驟，直接轉述給我並發通知。
- 執行 python rescue_dd.py bad，列出上一輪之後新增的壞檔（超過 10 個只列前 10 個）。
  提醒我：缺的比例是暫時的，全部讀完後會補讀。

判斷「卡住」的方法：
- 看回報裡「已讀到」的資料量有沒有增加。**不要只看速度 0.0 MB/s 就說硬碟掛了**，
  讀到資料稀疏的區段時速度本來就是 0；也不要只看讀取位置，ddrescue 重啟時位置會跳回範圍開頭。
- 一輪剛開始時顯示 0%、某一次「釋放 0.00 GB」，都是正常的。
- 程式自己會處理卡住：累計 45 分鐘沒讀到新資料，就把那一段記成危險區、跳過，留到最後補讀。你照常轉述就好。
- 補讀（retry）時「已救回」好幾個小時都沒增加是正常的；危險區的檔案數往上增加也是正常的（程式跳過卡點）。

以下是正常狀況，照常轉述、不用處理：
- 「讀滿 120 分鐘，休息 60 分鐘（自動繼續）」
- 「G 槽只剩 … 暫停讀取與輸出，等 Google Drive 上傳釋出空間」（超過 3 小時沒恢復才提醒我檢查 Google Drive）
- 「ddrescue 結束但範圍還沒讀完 …，硬碟有回應，繼續」
- 「已 N 分鐘沒讀到新資料（讀取位置 X GB），硬碟還在，繼續等」
- 「硬碟在 X GB 卡住 N 分鐘，跳過這一段繼續讀其他位置」

== 一輪結束 ==
輸出最後會有「===== … 結束 =====」：
1. 讀 <WORK>\ddrescue批次報告_bNN.txt（資料夾模式是 ddrescue批次報告_資料夾.txt），完整轉述給我。
2. 告訴我壞檔清單在 <XLSX> 的「壞軌檔案清單」工作表（可依批次篩選）。
3. 停止 /loop，等我確認才開始下一輪。

== 要停下來叫我的狀況 ==
- 「★★★ 硬碟掉回 Windows 了 ★★★」→ 立刻請我拔掉硬碟 USB。
- 「硬碟掉線了」「硬碟卡死或沒接上」→ 轉述拔插步驟：關硬碟電源 → 等 10 秒 → 開電源 →
  立刻在 VMware 選單 VM → Removable Devices → <硬碟名稱> → Connect。
- 「虛擬機沒有回應」、vm-check 失敗、SSH 逾時。
- 「ddrescue 已結束且沒有任何進度」。
- 「C 槽剩不到 50 GB」。
- 「壞檔清單 Excel 更新失敗」→ 先請我關閉那個 Excel 檔。
- 任何 Traceback（Python 錯誤）。
- 背景任務結束，卻沒有「===== … 結束 =====」，也沒有上面這些訊息。

== 虛擬機重開機之後 ==
請我在虛擬機畫面依序打以下四行，每行按 Enter：
  dmesg -n 1
  echo root:rescue | chpasswd
  iptables -P INPUT ACCEPT
  iptables -F
（開機選單要先按 e，在 linux 那一行尾端加上 modprobe.blacklist=amd64_edac）
然後在 VMware 選單 Connect 硬碟（硬碟要接 USB 2.0 埠）。

== 全部批次讀完之後 ==
不要自己往下做，通知我：下一步是 close（資料夾模式救完的批次）→ retry → extract --final → 收尾，由開發用的 AI 執行。
```

## 讓 AI 真的會回報：監控程式要會結束

AI 沒有計時器，只有兩種情況會被喚醒：使用者傳訊息，或背景任務結束。所以：

- 用 `/loop` 讓 AI 定期回來看。
- 或是讓監控程式**達到門檻就結束**，例如 `python tools/狀態.py --until 75`（完成度到 75%，或 `需要處理.txt` 有內容時結束）。只會寫日誌、永遠不結束的監控程式，等於一個不會響的鬧鐘。
- 監控用的腳本寫成固定檔案，寫完先在前景跑一次，逐欄對照原始資料。不要每次用 heredoc 現寫（反斜線會被吃掉）。
