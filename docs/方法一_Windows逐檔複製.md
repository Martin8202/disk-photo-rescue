# 方法一：Windows 逐檔複製（`method1_windows_copy/rescue.py`）

透過 Windows 檔案系統，一個檔案一個檔案從故障碟複製到目的地。壞檔跳過並記錄，健康的先搬完，最後才回頭慢慢救壞檔。

**適用**：硬碟只有零星壞軌，Windows 還能正常列出資料夾。
**不適用**：已經出現整顆卡死、USB 反覆重置、MFT 損毀、當機。這些情況請直接用[方法二](方法二_虛擬機ddrescue.md)。

## 它怎麼運作

分兩個階段：

| 階段 | 做什麼 | 碰到壞檔 |
|---|---|---|
| `phase1` | 依資料夾名稱順序搬完所有讀得到的檔案。目的地已有同大小、同修改時間的檔案就跳過，所以中斷後重跑同一行指令就會續傳 | 立刻跳過、記進 CSV，不重試 |
| `phase2` | 回頭處理 phase1 跳過的資料夾與壞檔 | 先普通讀一次；失敗就改成每 4 KB 慢慢讀，讀不到的地方補 0 |

保護機制（都是實際出過事才加的，來由見[演進過程](演進過程.md)）：

- **卡住的判斷看「多久沒讀到新資料」**，不看一個檔案讀了多久，所以大影片只要有進度就不會被誤判。超過 `STALL_SEC`（180 秒）沒有進度，回報就顯示「卡在壞軌」。
- **單一檔案 10 分鐘完全沒進度**（`FILE_STALL_KILL_SEC`）：把它記成「卡住(壞軌)」，啟動一個小幫手程序 `taskkill` 掉主程式，等主程式真的消失（卡在核心的讀取要 15～45 分鐘才會放棄）後，用同樣的參數自動重跑、跳過這個檔。自動重跑後一個檔都還沒成功又卡住，代表是硬碟卡死而不是檔案壞了，這時就停下來等人拔電源。
- **同一個資料夾連續 5 個檔失敗**（`CONSEC_FAIL_LIMIT`）：這個資料夾剩下的整批留給 phase2，換下一個資料夾。原本的做法是「休息 5 分鐘」，實測休息完照樣失敗，因為那是實體壞區。
- **硬碟卡死偵測**：連續 3 個資料夾讀不到清單，或連續 2 個資料夾被延後而中間一張都沒成功，就用不經快取的方式讀一個確定完好的檔案（`PROBE_FILE`）。30 秒讀不到就判定硬碟卡死，撤銷這段期間的紀錄並停止。沒有這個機制，硬碟卡死時每個資料夾都會被誤記成「讀不到」。
- **來源讀取錯誤和目的地寫入錯誤分開算**。Google Drive 鎖檔或暫存區滿造成的寫入失敗，等 60 秒重試，不會被當成壞軌。
- **G 槽剩不到 20 GB 就暫停**，等 Google Drive 上傳釋出空間後自動繼續。
- **絕對不做 USB 裝置重置**。曾經有版本在卡住時用 `pnputil /restart-device` 重啟 USB，結果直接藍屏（0x50）。

## 準備

1. 安裝 Python（實際使用 3.14）與 `pip install -r requirements.txt`（只有 openpyxl）。
2. **以系統管理員執行 `scripts/準備硬碟.bat`，再接上硬碟**。它會關掉自動播放、NTFS 最後存取時間、Spot Verifier、Chkdsk 背景掃描，並把硬碟設成唯讀。沒做這一步，Windows 會在背景反覆讀 MFT，讓 USB 每 16 秒重置一次。
3. 打開 `method1_windows_copy/rescue.py`，修改最上方「可調參數」：

| 參數 | 說明 |
|---|---|
| `SRC_ROOT` / `DST_ROOT` | 主要來源與目的地（這次是 `E:\照片` → `G:\...\照片`） |
| `OTHERS_SRC` / `OTHERS_DST`、`PRESETS["others"]` | 「其他資料夾」模式的來源、目的地根目錄與要搬的第一層資料夾 |
| `WORK` | 工作檔目錄（CSV、日誌、鎖定檔）。**放本機 C 槽，不要放雲端硬碟**，同步時會被鎖住 |
| `REPORT_TXT` / `XLSX` | 進度回報與壞檔清單。放雲端硬碟的話，手機也看得到 |
| `PROBE_FILE` | 一個確定完好、已經搬好的檔案，用來判斷硬碟還有沒有回應 |
| `KNOWN_BAD` | 已知會卡很久的壞檔，phase1 完全不讀，直接留給 phase2 |

4. 自我測試（用假資料，不碰硬碟）：

```powershell
python method1_windows_copy\rescue.py --selftest     # 最後一行要是 SELFTEST OK
```

5. 先用一個小資料夾試跑：

```powershell
python method1_windows_copy\rescue.py phase1 --only "某個小資料夾"
```

## 啟動

照 A → B → C 的順序試，前一個確認失敗才換下一個。**判斷有沒有啟動成功**：等 30 秒，`WORK\rescue.lock` 存在，而且 `WORK\進度紀錄.log` 最後幾行出現「第一階段開始」。

- **A. 雙擊 bat**，或請檔案總管代開：`explorer.exe "...\method1_windows_copy\開始第一階段.bat"`
- **B. 工作排程器**（程式會在桌面開視窗，跟 AI 工具的 shell 無關）：
  ```powershell
  $a = New-ScheduledTaskAction -Execute '...\method1_windows_copy\開始第一階段.bat'
  Register-ScheduledTask -TaskName 'PhotoRescue-Phase1' -Action $a -Force | Out-Null
  Start-ScheduledTask -TaskName 'PhotoRescue-Phase1'
  ```
  工作名稱用 `PhotoRescue` 開頭，收尾時恢復腳本才會把它一起清掉。
- **C. 最後手段**：在終端機背景執行 `python rescue.py phase1`。AI 工具的指令逾時或對話結束時，程式可能被一起關掉（不過可以續傳）。

實測 AI 工具用 `Start-Process` 開出去的視窗不一定真的有在跑，所以不列入選項。

| 要做的事 | 指令 |
|---|---|
| 其他資料夾 | 雙擊 `開始其他資料夾.bat`（等於 `rescue.py phase1 --tops others`） |
| 改完程式換成新版 | `python rescue.py --restart`（或 `--restart others`、`--restart phase2`）：結束舊版、等它真的結束，再用方法 A 啟動新版。印出「請直接再執行一次」就再執行一次 |
| 中斷 | 在程式視窗按 `Ctrl+C`，之後再雙擊一次就會接續 |

程式執行期間會自動阻止電腦睡眠。**電腦不要關機，Google Drive 不要暫停同步。**

## 監控

- **視窗標題列**每 2 秒更新：階段、狀態、目前檔名、這個檔讀了幾秒。秒數有在跳就代表程式還活著。
- **每 5 分鐘**寫一次 `REPORT_TXT`（進度回報.txt），也同時印在視窗上、寫進 `進度紀錄.log`。
- 給 AI 監控用：`python rescue.py --wait-report` 會等到下一次回報出現才印出來結束（最多 6 分鐘）；`--wait-report 0` 立刻印出目前這份。監控指令範本見[監控AI指令範本](監控AI指令範本.md)。

### 回報狀態怎麼看

| 狀態 | 意思 | 要做什麼 |
|---|---|---|
| 執行中 | 正常 | 不用做事 |
| 卡在壞軌（已經 N 分鐘沒有讀到任何資料） | Windows 正在重試讀壞軌，**這是正常的** | 不要關程式 |
| E 槽斷線，等待重新連接 | USB 斷了 | 檢查 USB 線與電源；接回後會從同一個檔案繼續，斷線不會被記成壞軌 |
| 已記成卡住(壞軌)，強制結束程式並自動重新啟動 | 單一檔案卡超過 10 分鐘，程式自己在處理 | 不要自己執行 `--restart` |
| 程式強制結束中…已等 N 分鐘 | 小幫手在等卡住的讀取被 Windows 放棄 | 照常等；超過 60 分鐘才需要關心 |
| 硬碟疑似卡死，程式已自動停止 | 連確定完好的檔案都讀不到 | **拔掉硬碟電源讓它休息**，再重新啟動 |
| 等 Google Drive 上傳釋出暫存空間 | 搬得比上傳快 | 照常等；連續 2 小時以上才檢查 Google Drive 有沒有在上傳 |
| 備註：xlsx 正被開啟 | Excel 開著壞檔清單 | 關掉 Excel |

## 第二階段

phase1 全部做完、回報過之後才開始：

```powershell
python rescue.py --restart phase2
```

處理順序是「趁硬碟還活著，先救成功機會大的」：
1. 清單讀得到、只是因為裡面有壞檔而整批延後的資料夾（裡面通常有幾千張好照片）
2. 清單讀取逾時的資料夾
3. 結構損壞的資料夾
4. 最後才一個一個救個別壞檔（小檔先）

單一檔案花在壞區的時間上限 20 分鐘（`P2_BAD_TIME_CAP_SEC`）、總時間上限 60 分鐘（`P2_FILE_TIME_CAP_SEC`），超過就補 0。

## 產出

| 檔案 | 內容 |
|---|---|
| 目的地資料夾 | 救回的檔案，還原修改時間 |
| `原檔名_部分損壞.JPG` | 只救回一部分的檔案，壞區補 0。**不用原檔名**，避免被當成好檔 |
| `XLSX` 的「無法複製清單」 | 只列真的因壞軌失敗的檔案或資料夾（黃：待救援、紅：無法讀取、橘：部分救回，附救回比例） |
| `WORK\壞軌紀錄.csv` | 程式的完整紀錄，包含暫時性錯誤。**不要手動修改** |

錯誤代碼：`23` CRC 錯誤、`1117` I/O 錯誤、`13`/`22` 讀取失敗（這顆碟退化後最常見），都算壞軌；`1392` 檔案或目錄結構損壞；`121` 逾時；`32` 檔案被佔用（暫時性，phase2 重試通常就好）。

## 收尾

救援全部結束、硬碟拔掉之後，以系統管理員執行 `scripts/恢復Windows自動修復.bat`，把準備硬碟時關掉的設定、救援用的排程工作都恢復原狀。完整步驟與檢查方法見[收尾：讓電腦恢復原狀](收尾_恢復電腦原狀.md)。

## 可調參數一覽

| 參數 | 預設 | 作用 |
|---|---|---|
| `REPORT_EVERY_SEC` | 300 | 回報間隔 |
| `STALL_SEC` | 180 | 多久沒進度算「卡住」（這顆碟一般壞軌 50～60 秒就會報錯） |
| `FILE_STALL_KILL_SEC` | 600 | 單一檔案多久沒進度就強制跳過 |
| `CONSEC_FAIL_LIMIT` | 5 | 同一資料夾連續失敗幾個就整批延後 |
| `HUNG_DIR_LIMIT` / `HUNG_DEFER_LIMIT` | 3 / 2 | 觸發硬碟卡死探測的門檻 |
| `MIN_FREE_GB_ON_G` | 20 | 目的地剩多少 GB 就暫停 |
| `P2_BAD_TIME_CAP_SEC` / `P2_FILE_TIME_CAP_SEC` | 1200 / 3600 | phase2 單一檔案的時間上限 |
| `P2_REST_BETWEEN_FILES` | 10 | phase2 每個檔案之間休息幾秒 |
