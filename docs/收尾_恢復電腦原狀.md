# 收尾：讓電腦恢復原狀

救援期間，為了保護故障碟、架設虛擬機環境，對 Windows 做了不少改動。全部救完之後照這一頁還原。

## 什麼時候做

全部完成之後才做，依序：

1. 救援收尾：方法二是 `close`（資料夾模式救完的批次）→ `retry` → `extract --final`，見[方法二](方法二_虛擬機ddrescue.md)的「收尾」。
2. 壞檔清單（XLSX）與批次報告都看過了。
3. Google Drive 已經上傳完（工作列的 Google Drive 圖示沒有待上傳項目）。
4. 在 VMware 選單 Disconnect 硬碟 → 關閉虛擬機 → **拔掉硬碟**。
5. 做下面三個步驟。

**硬碟一定要先拔掉。** 恢復腳本會把 Windows 對硬碟的保護拿掉（自動修復、背景掃描、自動播放），故障碟還接著的話，Windows 可能馬上開始掃描、「修復」它。

## 第一步：執行恢復腳本

以系統管理員身分執行 `scripts/恢復Windows自動修復.bat`。它會還原：

| 救援時做的改動 | 誰做的 | 恢復腳本怎麼處理 |
|---|---|---|
| 關閉自動播放（登錄 `NoDriveTypeAutoRun`） | `準備硬碟.bat` | 刪除這個設定，回到預設 |
| 關閉 NTFS 最後存取時間（`disablelastaccess 1`） | `準備硬碟.bat` | 改回系統管理（`disablelastaccess 2`） |
| 停用 Spot Verifier 服務 | `準備硬碟.bat` | 改回手動 |
| 停用 Chkdsk 背景掃描排程（ProactiveScan） | `準備硬碟.bat` | 重新啟用 |
| 救援用的排程工作（`PhotoRescue-ResetE`、「照片搬移第一階段／第二階段／其他資料夾」等） | 方法一的啟動方式 B、舊版程式 | 刪除所有 `PhotoRescue` 與「照片搬移」開頭的排程工作 |
| SMB 共用 `PhotoRescueDD` | `setup-host.ps1` | 移除 |
| 防火牆規則 `PhotoRescue VM SMB` | `setup-host.ps1` | 移除 |
| 本機帳號 `photorescue`，以及讓它不出現在登入畫面的登錄設定 | `setup-host.ps1` | 兩個都移除 |
| 故障碟設成唯讀 | `準備硬碟.bat` | 硬碟已經拔掉的話不會動，硬碟維持唯讀，對一顆要退役的故障碟正好 |
| 故障碟上 NTFS 的自我修復（`fsutil repair set E: 0`） | `準備硬碟.bat` | 這是記在那顆硬碟上的設定，跟著硬碟一起退役，不用處理 |

## 第二步：檢查有沒有恢復乾淨

在 PowerShell 貼上執行（只查不改）：

```powershell
Get-ScheduledTask | Where-Object { $_.TaskName -like 'PhotoRescue*' -or $_.TaskName -like '照片搬移*' } | Select-Object TaskName
(Get-ScheduledTask -TaskPath '\Microsoft\Windows\Chkdsk\' -TaskName ProactiveScan).State
(Get-CimInstance Win32_Service -Filter "Name='svsvc'").StartMode
fsutil behavior query disablelastaccess
Get-ItemProperty 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer' -Name NoDriveTypeAutoRun -ErrorAction SilentlyContinue
Get-SmbShare -Name PhotoRescueDD -ErrorAction SilentlyContinue
Get-NetFirewallRule -DisplayName 'PhotoRescue VM SMB' -ErrorAction SilentlyContinue
Get-LocalUser -Name photorescue -ErrorAction SilentlyContinue
```

恢復乾淨的樣子：

| 指令 | 應該看到 |
|---|---|
| 排程工作 | 沒有輸出 |
| ProactiveScan | `Ready` |
| svsvc | `Manual` |
| disablelastaccess | `System Managed` |
| NoDriveTypeAutoRun、SMB 共用、防火牆規則、本機帳號 | 都沒有輸出 |

這次救援期間的實際狀態是：ProactiveScan `Disabled`、svsvc `Disabled`、disablelastaccess `1`、NoDriveTypeAutoRun `255`、4 個排程工作、共用、防火牆規則、帳號都在。恢復之後應該全部變成上面那張表的樣子。

## 第三步：手動清理（自己決定）

這些不會自動刪，要確認資料都安全之後自己處理：

| 項目 | 位置 | 這次的大小 | 建議 |
|---|---|---|---|
| 映像檔與 mapfile | `C:\PhotoRescueDD` | 邏輯 2.8 TB，實際佔用約 259 GB（稀疏檔） | 確認 G 槽都上傳、壞檔清單看過之後刪除。映像檔只含讀過的範圍；還想用 PhotoRec 這類特徵掃描工具再撈東西的話，先留著 |
| 虛擬機 | `C:\PhotoRescueVM` | 約 2.8 GB（SystemRescue ISO 1.3 GB） | 刪除。SSH 密碼檔 `askpass.cmd`、SMB 帳密 `share-password.txt` 也在裡面 |
| 工作資料夾 | `C:\照片救援` | 約 16 GB，大部分是 `dd_tmp`（14 GB，還沒輸出完的暫存） | `extract --final` 之後 `dd_tmp` 可以清掉。建議留下 `dd.sqlite`（約 200 MB，每個檔案的救援結果）、`壞軌紀錄.csv`、批次報告當紀錄，其他刪除 |
| VMware Workstation | 設定 → 應用程式 | — | 之後用不到就解除安裝 |
| 整理作品集用的 worktree | `C:\照片救援\repo-portfolio` | — | PR 合併之後執行 `git worktree remove` |
| 故障硬碟本身 | — | — | 退役，不要再存資料。要丟棄的話，裡面有家人的照片與個人資料，先做實體破壞 |
