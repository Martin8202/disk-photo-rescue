# disk-photo-rescue：壞軌硬碟照片救援

一顆 3 TB 的外接硬碟（Seagate Expansion Desk）裡存著全家二十年的照片。它開始壞軌、會整顆卡死，還讓 Windows 當機了兩次。這個專案是在十天內把資料救出來的完整過程：兩種救援方法、所有程式、操作手冊，以及一路踩過的坑。

整個專案是和 Claude Code 協作完成的：**人負責判斷，AI 負責執行**。救什麼、不救什麼、先救哪些、什麼時候可以放手讓它自動跑，都由我決定；規劃、寫程式、分析當機原因由 Claude（Opus）負責；長時間的監控與定時回報交給另一個執行用的 AI。

| 方法一（Windows 逐檔複製） | 約 10 萬張照片 + 15,350 個其他檔案 | — |
| 方法二（虛擬機 + ddrescue）從故障碟救回 | **223,474** | **1,203 GB** |
| 另外存成「部分損壞」的照片（壞區 ≤ 5%） | 6 | — |
| 從舊備份碟直接補回（不用讀故障碟） | 8,093 | 35 GB |
| 比對後判定是重複、不用讀 | 4,943 | 8.5 GB |
| 救不回來（壞區太多 114 個、在會讓硬碟鎖死的位置沒讀 19 個） | 133 | 0.65 GB |

方法二的範圍共 262,434 個檔案，每一個的去向都能對帳，明細見[演進過程](docs/演進過程.md)的「成果」一節。

## 兩種方法

```
                 ┌─ 零星壞軌、Windows 讀得動 ──────────────▶ 方法一：Windows 逐檔複製
  故障硬碟 ──判斷─┤
                 └─ 卡死、USB 反覆重置、MFT 損毀、當機 ────▶ 方法二：虛擬機 + ddrescue
```

| | 方法一 | 方法二 |
|---|---|---|
| 程式 | `method1_windows_copy/rescue.py` | `method2_vm_ddrescue/rescue_dd.py` + `rescue2.py` |
| 做法 | 透過 Windows 檔案系統逐檔複製；壞檔跳過並記錄，健康的先搬完，最後再回頭慢慢救 | 硬碟 USB 直通進 Linux 虛擬機，用 GNU ddrescue 唯讀讀磁區；Windows 端自己解析 NTFS 的 MFT，只讀還沒救到的檔案所在的位置 |
| 碰到壞軌 | Windows 重試 60～400 秒，無法中斷 | 讀不到就跳過、記下位置，全部讀完再回頭補讀 |
| 目錄壞掉的檔案 | 找不到 | 從 MFT 找回來 |
| 硬碟卡死時 | 整台電腦可能藍屏或凍結 | 通常只是虛擬機卡住 |

方法二的架構：

```
 Windows 主機                                   VMware 虛擬機（SystemRescue）
 ┌─────────────────────────────┐    SSH     ┌──────────────────────────────┐
 │ rescue_dd.py 控制程式         │──────────▶│ ddrescue（唯讀）               │
 │  解析 MFT、分批、看門狗、輸出   │            │   ▲ USB 直通                  │
 │ C:\PhotoRescueDD\            │◀── SMB ────│ /mnt/dd                      │
 │  稀疏映像檔 + mapfile          │            └───┼──────────────────────────┘
 └──────────────┬──────────────┘                故障硬碟（Windows 看不到）
                ▼
         Google Drive（原本的資料夾結構、原本的修改時間）
```

## 設計重點

- **只讀不寫**：故障碟在虛擬機裡設成唯讀；Windows 完全看不到它，也就不會自動掛載、重放 NTFS 日誌或「修復」目錄。
- **先救目錄**：第一步只讀 2 GB 的 MFT。就算硬碟之後死了，也知道原本有什麼、少了什麼。
- **只讀需要的**：比對目的地、比對重複檔、先找舊備份。3 TB 的硬碟，最後只需要讀 1.3 TB。
- **分批、邊讀邊交付**：13 批，每批約 100 GB；讀完就輸出到雲端，映像檔的空間在不夠時才釋放。
- **只有輸出到目的地的才算數**：每批開始前，把「標記讀到但還沒輸出」的範圍改回未讀，當機或延遲寫入失敗也不會留下空檔案。
- **看門狗在虛擬機外面**：硬碟卡死時 ddrescue 自己的逾時不會生效。控制程式分辨「卡住（等）」和「掉線（叫人）」，會讓硬碟鎖死的位置記成危險區，改成離危險區越遠的先讀。
- **會叫人的自動化**：一批接一批自動跑，任何異常就停下來，寫一個說明原因與處理步驟的旗標檔。

## 測試

不需要硬碟，也不需要虛擬機：

```powershell
pip install -r requirements.txt
python method1_windows_copy\rescue.py --selftest       # SELFTEST OK
python method2_vm_ddrescue\rescue2.py --selftest       # SELFTEST OK
python method2_vm_ddrescue\rescue_dd.py --selftest     # SELFTEST OK
python method2_vm_ddrescue\test_watchdog.py            # 全部通過
```

`rescue2.py` 的自我測試會自己產生一個迷你 NTFS 映像檔（含壞磁區、MFT 壞記錄、孤兒檔、屬性清單大檔、resident 小檔），`rescue_dd.py` 用它加上一個模擬 ddrescue 的替身，跑完整的「讀 MFT → 規劃 → 分批讀取 → 輸出 → 補讀 → 最終輸出」流程，並逐位元組比對救回的檔案。

## 注意

- 這是針對一顆特定硬碟、在 Windows 11 上開發的工具。換一顆硬碟前，務必照操作手冊檢查「可調參數」，特別是磁區大小與硬碟識別路徑。
- 硬碟有異音、完全不轉，或資料極為重要又沒有備份時，請先考慮專業資料救援。
- 虛擬機的 root 密碼刻意設得很簡單：虛擬機只存在於 VMware NAT 網段，外部連不進來，而且是用完就丟的環境。SMB 共用的密碼是執行時隨機產生的，不在 repo 裡。
- 程式與文件中的人名、資料夾名稱已換成通用範例（家人A／B／C）。
